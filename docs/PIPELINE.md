# Пайплайн File Cleaner

```
 ┌────────┐   ┌──────────────┐   ┌──────────────┐   ┌───────────────────┐   ┌───────────┐   ┌─────────┐
 │  Скан  │ → │   Проверка   │ → │  Сортировка  │ → │ Ready for approval│ → │Утверждение│ → │ Сжатие  │
 │ индекс │   │ анализаторы  │   │ секторы+типы │   │  ты смотришь сам  │   │ удаление  │   │ холодное│
 └────────┘   └──────────────┘   └──────────────┘   └───────────────────┘   └───────────┘   └─────────┘
      │               │                   │                                        │             │
      └───────────────┴──────── журнал (journal/*.jsonl) → undo ───────────────────┘─────────────┘
```

## 1. Скан — `index.py`

Один проход по папкам из `[scan] roots`. Для каждого файла в SQLite: путь, размер, даты, атрибуты,
признак «внутри программы/проекта», облачный ли (OneDrive), откуда скачан (`Zone.Identifier`).
Хэши (начало+конец и полный) кэшируются по (путь, размер, дата) — повторная проверка не перечитывает диск.

Защита на этом этапе (`fsutil.walk`): не заходит в системные папки, AppData, игры, `node_modules`,
скрытые системные папки, по ссылкам и junction. Папки проектов (`.git`, `package.json`, `.sln`…)
и программ (есть `.dll`) помечаются: их файлы по одному не трогаются, только папка целиком.

## 2. Проверка — `analyzers.py`

Независимые анализаторы, каждый возвращает `Finding`: файл, правило, режим, причина человеческим языком.

| Анализатор | Что ищет | Режим по умолчанию |
|---|---|---|
| `system_junk` | temp старше 2 дней, кэши браузеров и программ, дампы сбоев | delete |
| | кэш pip/npm, Корзина | report |
| | кэш шейдеров видеокарты | off |
| `user_junk` | `Thumbs.db` | delete |
| | `~$*.docx`, `.tmp`, недокачанные `.crdownload/.part` | review |
| `empty_dirs` | пустые папки в Загрузках и на Рабочем столе | delete (undo вернёт) |
| `duplicates` | одинаковые папки целиком; копии рядом, с именем-копией, лишние в Загрузках | review |
| | копии в разных «осмысленных» папках | report |
| `extracted_archives` | архив + рядом папка с тем же содержимым (для zip — сверка файлов) | review |
| `installers` | установщик уже установленной программы; старая версия, если есть новее | review |
| `vm_disks` | `.vdi`, не подключённый ни к одной виртуалке VirtualBox | review |
| `old_files` | большие файлы, которые давно не менялись | report |

Затем `resolve` (у файла одна, самая сильная причина; файлы внутри найденной папки не дублируются)
и `apply_protection` (ключевые слова и папки из `[protect]` → только отчёт).

## 3. Выполнение проверки — `pipeline.py`

`delete` удаляются сразу (это восстанавливается само), `review` переезжают в `Ready for approval`
(`review.stage`): на каждом диске своя папка, внутри подпапки по причинам с сохранением пути,
`ОТЧЁТ.html`, `КАК ПОЛЬЗОВАТЬСЯ.txt`, `_ВЕРНУТЬ` и `.manifest.json` (что откуда).

## 4. Сортировка — `organizer.py`

Для каждого файла в корне папки:
1. тип по расширению + подпапка по смыслу (скриншоты, фото с камеры, записи экрана);
2. сектор: сайт-источник → ключевые слова в имени → тип;
3. если сектор не найден и включён ИИ — локальная модель по имени и началу текста;
4. назначение: `<сектор>/<тип>/…` или `<тип>/…`; сектор или тип можно переселить на другой диск (`target`, `type_targets`);
5. если в назначении уже лежит такой же файл — это дубликат, он уходит в `Ready for approval`.

Подпапки переносятся целиком, только если понятно куда (ключевое слово, 80% содержимого одного типа,
дистрибутив с `setup.exe`/`.msi`).

## 5. Чтобы программы не потеряли файлы — `refs.py`

- `scan_references`: пути в реестре `HKCU\Software` и в настройках программ в `AppData` → какие программы помнят какие файлы;
- файл помнит программа → `leave_link`: символьная ссылка (файл) или junction (папка) на старом месте;
- `update_office_mru`: пути в «Недавних документах» Office переписываются;
- `update_shortcuts`: ярлыки на Рабочем столе, в Пуске и в «Недавних» Windows переписываются (через WScript.Shell).

Каждое изменение пишется в журнал со старым значением — `undo` возвращает всё.

## 6. Утверждение — `review.approve`

Содержимое `_ВЕРНУТЬ` сопоставляется с манифестом (по пути внутри папки и размеру) и возвращается
на прежние места; остальное из манифеста удаляется. Чужие файлы и то, что не удалось опознать, не трогаются.

## 7. Сжатие — `compress.py`

Оценка по выборке (как сожмёт Windows кусками по 32 КБ), кандидаты — файлы, которые станут меньше
хотя бы на 15%. `compact /c /exe:LZX` — прозрачно для программ; `undo` → `compact /u /exe`.

## Журнал — `journal.py`

Каждая операция — файл `journal/<время>-<вид>.jsonl`, записи дописываются сразу (сбой ничего не потеряет):
`move`, `stage`, `mkdir`, `rmdir`, `delete`, `link`, `reg_set`, `lnk_set`, `compress`, `batch`.
`undo` проходит их в обратном порядке. Необратимо только `delete` (кэши и утверждённое удаление).
